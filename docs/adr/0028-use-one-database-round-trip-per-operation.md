# Use one database round trip per operation

Every successful operation performs exactly one PostgreSQL statement and round trip at `READ COMMITTED` isolation as its own autocommit transaction, with no explicit transaction-control round trips: registration hashes then inserts and returns the User; login selects then verifies and signs; Short Link creation verifies then inserts and returns the Short Link; resolution atomically updates click analytics and returns the destination; statistics verification is followed by one select that returns ownership and analytics. Each request gets one statement attempt with no query retry, reconnect-and-replay, or application retry loop; pool waiting is allowed within the request timeout, and failures count against the error budget. Contenders may generate SQL idiomatically but may neither split these interactions nor combine work across requests.
