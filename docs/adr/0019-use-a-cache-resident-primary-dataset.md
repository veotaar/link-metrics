# Use a cache-resident primary dataset

The canonical primary Benchmark Dataset contains 100,000 Users with ten Short Links each and is sized to fit comfortably within the configured PostgreSQL memory, with relevant pages warmed before measurement. For every User, five Short Links have zero Clicks and a null last-clicked time while five have deterministic nonzero counts and timestamps; the statistics Scenario selects evenly across both states. Every seeded User has the same benchmark-only plaintext password but a distinct precomputed Argon2id hash and 16-byte salt, preventing hash-value or verification caching; one-time dataset construction cost is excluded from Trials. This focuses primary results on backend-stack, SQL, synchronization, and cryptographic costs rather than variable storage latency; larger-than-memory data is reserved for a separately reported scenario family.
